## 1. 当前项目实际依赖什么

| 组件 | 事实（来自源码与文档） | 合规含义 |
| --- | --- | --- |
| 战斗引擎 | 用户自行提供的第三方客户端 APK（README 标注为 15.535.13 版本），由 `offline_build.py` 注入原生探针、重新签名并安装到本地 VM | 本质上是**修改游戏客户端**并调用其内部函数。即使完全离线，Supercell 条款通常也禁止修改、逆向或使用未授权客户端；风险由使用者自担。仓库本身不分发 APK（见 NOTICE），这一点降低了分发风险，但没有消除使用风险 |
| 网络 | 探针包含离线连接保护（`g_offline_control_session_active`、`offlineConnectionErrorsSuppressed`），NOTICE 声明不连接官方服务器 | 与“不进行线上自动化”的目标一致；任何改动都应保持这一保护，并加测试 |
| 训练数据 | Hugging Face `IL_Replay`：25.2 万局回放，schema `royaleapi-battle-replay.v1`，含玩家 tag | 数据来源于第三方站点的回放，需确认其使用条款；玩家 tag 属于可识别信息，再分发前建议去标识化 |
| 线上成绩 | `training_history.md` 记录作者“使用速猪模型的账号打上名人堂” | 若对局中由程序代为操作，属于官方条款明确禁止的机器人/自动化。**本项目不复现、不扩展这一做法** |

## 2. 真实游戏适配：技术上需要什么，以及为什么不做

把离线模型接到真实对局，需要三层：

1. **感知**：屏幕截图 → 目标检测/分割识别单位、塔血、圣水、手牌。离线引擎提供的是精确结构化状态，真实画面只能估计，存在明显的 sim-to-real 差距（遮挡、动画、隐藏信息）。
2. **状态对齐**：把视觉估计转换成 `ObservationV1`，包括对手卡组循环、圣水推断，`FAIR` 可见性契约需要重新校准。
3. **执行**：向设备注入触控（ADB、无障碍服务、模拟器宏）。

第 3 层就是线上自动化，第 1–2 层一旦实时用于对局决策，也构成第三方辅助。两者都违反游戏条款，并可能导致封号；Supercell 有反作弊检测。**因此本项目不实施任何线上感知或执行代码。**

### 合规的替代方向

| 方向 | 说明 |
| --- | --- |
| 纯离线研究 | 在本地引擎上训练、评估、对战（当前项目的主体）。建议仅用于个人研究，不分发修改后的客户端 |
| 赛后复盘 | 对自己已结束的对局做离线分析：把回放导入引擎，比较“模型会怎么出”与实际出牌，生成复盘报告。不在对局中实时提示 |
| 官方 API 的只读数据 | 使用官方开发者 API 读取公开对战记录做统计（卡组胜率、版本分析），遵守其开发者条款与频率限制 |
| 自研模拟器 | 长期看，用公开数值编写独立、不含原客户端代码的简化模拟器，可彻底摆脱客户端依赖，也便于大规模并行（见路线图 P3） |

## 3. 离线对战与评估机制（本分支已实现）

详见 [evaluation.md](evaluation.md)。要点：

- 镜像赛程：同一种子下交换座位与卡组，消除座位/卡组偏差。
- 可续跑：每局一个稳定 `game_id`，中断后跳过已完成局；部分写入的最后一行会被丢弃。
- 失败隔离：引擎异常记为 `status: "error"`，不影响统计；超过 `--max-errors` 停止。
- 统计：Wilson 区间、Elo、Bradley–Terry 多模型评分、SPRT 晋级门。
- 泛化：每个模型 × 每套卡组的得分表；配合 `--fixed-deck-a` 做专精评测。
- 行为指标：出牌数、首次出牌时间、满费停留时间，检测“被动刷胜率”。

## 4. 本分支发现并修复的问题

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| `test_probe_core_json` 的长度与哈希按 Windows CRLF 输出写死 | 在 Linux/macOS 上必定失败，CI 无法跑全量测试 | 先统一为 LF 再比较；已验证 CRLF 版本与原哈希完全一致 |
| CI 只运行 9 个测试文件 | 大部分回归（模型、tensorizer、PPO）不受 CI 保护 | CI 改为运行全量测试（CPU 约 1.5 分钟），并对新模块运行 ruff |
| `evaluate.py` 卡组随模型固定、种子不配对、无置信区间、无法复现历史强制首动作协议 | 胜率被卡组强弱和噪声污染；README 中的历史结果无法复现 | 抽取 `play_match`，新增 `--force-first-action-tick`、行为指标和 `report.json`；新增 `tournament.py` |
| 缺少 pytest 配置 | 在仓库根目录直接运行 `pytest` 会扫描无关目录 | `pyproject.toml` 增加 `testpaths` |

### 仍存在、未在本分支处理的问题（建议后续线程处理）

- `requirements.txt` 把 `wandb`、`pyarrow` 等训练依赖与推理依赖混在一起；只想对战或评估的用户也必须安装。建议拆成 `requirements-runtime.txt` / `requirements-train.txt`，或在 `pyproject.toml` 中声明 extras。
- 依赖只有顶层版本固定，没有锁文件（`uv.lock` 或 `pip-tools` 生成的哈希锁），可复现性依赖上游不变。
- `pyproject.toml` 没有 `[project]` 元数据，无法 `pip install -e .`。
- 官方安装流程只支持 Windows + MuMu；Linux 训练节点需要另一套 AVD 流程，两者没有共享的自动化检查。
- `battle_env.py`（4.7k 行）、`rich_telemetry_adapter.py`（4.4k 行）、`cr_native_env.py`（3.3k 行）体量过大，建议按观测构建、动作执行、遥测解析拆分。

## 5. 开发路线图

| 阶段 | 目标 | 交付物 | 验收标准 |
| --- | --- | --- | --- |
| P0（本分支） | 可信的评估与 CI | `tournament.py`、`eval_stats.py`、全量测试 CI、评估文档 | CI 全绿；模拟引擎测试覆盖赛程/续跑/SPRT |
| P1 | 复现历史结果 | 在真实离线引擎上用 focus 卡组池跑 General vs IL / Active IL，`--force-first-action-tick 300` | 结果落在 `training_history.md` 报告值的 95% 区间内；记录每小时局数 |
| P1 | 训练中的自动晋级门 | PPO 每 N 次更新保存快照后自动跑 SPRT 门，通过才进入 league | league 中不出现比上一快照显著更弱的模型 |
| P2 | 跨卡组泛化研究 | 留出卡组集（训练中从未出现）评测；按卡组原型（攻城、桥头、重坦、控制）汇总 | 报告留出卡组与训练卡组的得分差及置信区间 |
| P2 | 依赖与环境可复现 | runtime/train 依赖拆分、锁文件、`pip install -e .`、Linux 端到端安装检查 | 新机器按文档一次装好；`check_install.py` 通过 |
| P3 | 摆脱客户端依赖（可选，长期） | 独立的简化战斗模拟器，与原生引擎做行为一致性对照 | 在一组固定场景中，单位轨迹与塔伤误差在约定阈值内 |
| 持续 | 合规 | 保持离线连接保护测试；不加入任何屏幕识别/触控注入代码 | 代码审查清单中包含此项 |

## 6. 已验证与待验证

**已验证**（本分支，Linux CPU，Python 3.12，PyTorch 2.5.1）：

- 全量测试 1223 通过、18 跳过（CUDA、PowerShell、原始 APK 相关），修复前为 1 个失败。
- `check_release.py` 0 错误；`check_install.py` 5 个模型全部加载。
- 镜像赛程在模拟世界（设定模型强度 + 座位优势 + 卡组优势）中能分离出模型强度，Bradley–Terry 估计与理论值相差在 40 Elo 内。
- SPRT 门在强候选（+250 Elo）下提前停止并在块边界结束。

**待实验**（需要真实离线引擎，本环境无法运行）：

- 真实引擎下的对局吞吐和引擎异常后的恢复能力。
- 历史评测结果能否复现。
- 留出卡组上的泛化差距大小。
